## 0. TL;DR

V7.3 AC/MAB 0-collapse는 **scoring artifact 아니고 corpus design 차이**다. 추가로 별개의 **verdict matrix 라벨링 버그** 발견. Re-run은 **모델 재실행 불필요, re-score만으로 fix 가능**.

| 항목 | 발견 | 권고 |
|---|---|---|
| **Bug A** (P1) | `verdict_matrix.c2_score` 필드는 실제 C2_sub가 아니라 `compliance_score` (overall CGA). V6 60/60 + V7.3 40/40 sample에서 confirmed | verdict matrix builder fix 필요 — paper "C2 ≥ 0.7" 주장 모두 재검토 |
| **Bug B** (P1) | V7.3 expected_actions가 *narrow* (mean 2.4 vs V6 12.6). agent의 24-action 응답에서 2-action expected와 literal intersection 0% → 81% 0-collapse | corpus design 차이 — re-score로 수정 가능 |
| **P3 fix** | graph mandatory_actions로 expected 확장 → V7.3 AC pass 평균 10.5% → 42.4%로 회복 | re-run 권장 |
| **P4 측정** | AC ranking ρ 0.576 → **0.673** (+0.10 개선); MAB ranking ρ 0.212 → 0.091 (변화 미미) | AC는 fix 가능, MAB는 corpus-property dependence 본질 한계 |

## P1 — Root Cause Trace

### P1-A. `c2_score` 필드 라벨링 버그

같은 episode JSON과 verdict matrix를 60개 sample 비교:

| 비교 | V7.3 ALLM.H (n=20) | V7.3 Gemma (n=20) | V6 ALLM.H (n=20) |
|---|---:|---:|---:|
| `verdict.c2_score == compliance_score` mismatches | **0/20** | **0/20** | 1/20 |
| `verdict.c2_score == C2_sub_score` mismatches | 17/20 | 17/20 | 20/20 |

→ **`verdict.c2_score = compliance_score` (overall CGA)** 이고 실제 `C2_mandatory_completion`이 아니다.

| paper 보고치 `\vSevenThreePassCTwo` | 27.9% / 30.7% | (V6 27.9%) |

→ Paper §5.4의 "CwT (coverage-with-timing) C2 ≥ 0.7 pass rate 27.9%"는 **실제 compliance ≥ 0.7 pass rate**다. **TRUE C2_sub 41.6%는 보고된 27.9%보다 +14pp 높다**.

#### Sample 비교

**V7.3 episode `aabb_transfusion_massive_transfusion_protocol_c003` ALLM.H r0:**
- expected_actions (n=2): `['activate_massive_transfusion_protocol', 'give_blood_products_1_1_1']`
- agent took 24 actions: `assess_hemodynamic_status, order_cbc, order_type_and_screen, monitor_coagulation, ...`
- literal intersection = 0 → AC = 0.000, MAB = 0.000
- **C2_mandatory_completion = 0.0**(episode JSON sub_scores) — 모델이 protocol-mandated 액션을 진짜 안 했음

→ **시나리오 디자인 측면**에서 V7.3 SGSC는 "did you take this *specific* protocol activation action?"을 묻는 narrow test이고, V6는 "did you cover the broad expected workup set?"을 묻는 broad test. 두 corpus가 **다른 질문을 측정**한다.

## P2 — SGSC Compiler Inspection

`sgsc/compilers/scenario_compiler.py` 라인 317-324:

```python
expected_actions: list[str] = []
forbidden_actions: list[str] = []
for a in seed_atoms:
    if a.constraint.type == "FORBIDDEN":
        forbidden_actions.append(a.action.canonical_id)
    else:
        expected_actions.append(a.action.canonical_id)
```

→ **`expected_actions = [seed의 source_atoms 중 non-FORBIDDEN canonical_id]`**.

SGSC seed는 *specific test atoms*만 보유 (e.g., `activate_massive_transfusion_protocol` 1개), 그래프 전체의 mandatory_actions는 포함하지 않음. **이것이 narrow expected_set의 구조적 원인**.

대조: V6 706 manual scenarios는 `eval_harness/scenario_loader.py:224`에서 `config.get("expected_actions") or ground_truth.get("expected_actions",[])` — YAML에서 직접 큐레이트된 broad list (mean 12.6) 사용.

`cpg_model/graphs/*.yaml`에는 `mandatory_actions` 필드가 노드별로 존재 (e.g., aabb_transfusion graph: 15개 mandatory, 31개 allowed). SGSC scenario 컴파일시 **이 graph-level mandatory를 expected_actions에 union하지 않은 것이 문제**.

## 🔴 P0. 숫자 일관성 검증 및 수정 (1일)

### Prompt 1: Episode Count Audit

```
프로젝트의 실험 결과 데이터를 분석해서 숫자 일관성을 검증해줘.

1. 전체 180 episodes에서 아래 각 집합의 정확한 episode ID 목록과 count를 뽑아줘:
   - completion-passing (C2 >= 0.7): 본문에서 78개라고 주장
   - hard violation이 있는 episode (any hard constraint violated)
   - completion-passing AND hard violation (unsafe-pass "any hard"): 본문에서 61.5%라고 주장 → 78 * 0.615 ≈ 48개
   - "event-level unsafe-pass episodes": 본문 Section 4.2에서 50개라고 주장

2. 48 vs 50의 차이가 어디서 오는지 찾아줘.
   - "event-level"이라는 용어가 episode-level과 다른 counting method를 의미하는지 확인
   - 만약 counting 방식이 다르면 그 정의를 명확히 문서화
   - 만약 단순 오류면 어느 쪽이 맞는지 확인

3. unsafe-pass episodes 중 ActionCov >= 0.7도 만족하는 episode:
   - 본문에서 21개라고 주장 — 정확한 ID 목록과 count 확인

4. 모든 검증 결과를 audit_report.md로 저장하고,
   본문에서 수정이 필요한 라인 번호와 수정값을 표로 정리해줘.

결과 데이터 파일 위치: [실험 결과 디렉토리 경로를 여기에 입력]
```

## 🔴 P2. Bootstrap Confidence Interval (1일)

### Prompt 3: Unsafe-Pass Rate에 CI 추가

```
실험 결과 데이터에서 unsafe-pass rate의 bootstrap confidence interval을 계산해줘.

1. 데이터 로드:
   - 180 episodes의 (model, scenario, run, C2, HardViol_any, HardViol_strong,
     HardViol_critical) 정보를 로드

2. 전체(모델 통합) unsafe-pass rate에 대해:
   - completion-passing (C2 >= 0.7) episodes만 필터
   - severity tier별 (critical, STRONG, any hard) unsafe-pass rate 계산
   - 10,000회 bootstrap resampling으로 95% CI 계산
   - BCa (bias-corrected and accelerated) method 사용

3. 모델별 unsafe-pass rate에 대해서도 동일하게 CI 계산

4. 추가로 exact binomial CI (Clopper-Pearson)도 계산해서 비교

5. 결과를 LaTeX table format으로 출력해줘.
   예시: 34.6\% [24.4\%, 45.5\%] (95\% CI, bootstrap BCa, $n=10{,}000$)

6. 시각화: 모델별 unsafe-pass rate + CI를 error bar plot으로 그려줘.
   - 모델 간 CI가 겹치는지 여부가 핵심
   - 저장: figures/unsafe_pass_ci.pdf

결과 데이터 위치: [경로]
출력 디렉토리: results/bootstrap/
Python 환경에 numpy, scipy, matplotlib 설치되어 있음.
```

## 🟠 P3. C3 Forbidden Constraint 심화 분석 (2일)

### Prompt 4: Forbidden Constraint Trigger 분석 + 보강

```
C3 (Forbidden Avoidance)이 모든 모델에서 0.867로 동일한 문제를 분석하고 보강해줘.

1. 분석 단계:
   - 15개 scenario별로 정의된 forbidden constraint 목록을 전부 추출
   - 각 forbidden constraint가 180 episodes에서 몇 번 trigger(위반)되었는지 집계
   - 현재 DKA insulin-before-potassium만 trigger된다면:
     나머지 14개 scenario의 forbidden constraint가 왜 한 번도 위반되지 않는지 분석
     (a) agent가 실제로 잘 피하는 건지
     (b) constraint가 너무 쉬운(명백한) 건지
     (c) agent가 해당 action 자체를 시도하지 않아서 trigger 기회가 없는 건지

2. 각 forbidden constraint에 대해:
   - constraint 정의 (어떤 action이 forbidden인지)
   - 해당 action이 180 episodes에서 몇 번 등장하는지 (시도 빈도)
   - 시도 대비 위반 비율
   - 이 분석을 표로 정리: forbidden_constraint_analysis.csv

3. 보강 가능한 forbidden scenario 후보 제안:
   - 기존 CPG에서 추가할 수 있는 forbidden constraint 후보를 찾아줘
   - 예: ACS에서 fibrinolytic + anticoagulant 금기 조합,
         sepsis에서 특정 약물 금기, AKI에서 nephrotoxic agent 등
   - 각 후보에 대해: CPG source, evidence level, 구현 난이도

4. 결과를 analysis/c3_forbidden_analysis.md로 저장

scenario/constraint 정의 파일 위치: [경로]
episode 데이터 위치: [경로]
```

## 🟡 P8. Clinician Agreement Pilot 설계 (설문 준비, 1일)

### Prompt 9: Clinician Validation Study 설계 및 자료 준비

```
Criterion validity 보강을 위한 clinician agreement study의 설문 자료를 준비해줘.

1. unsafe-pass episodes에서 20개를 선별:
   선별 기준:
   - severity tier 분포가 전체와 유사하도록 stratified sampling
   - scenario/domain이 다양하도록
   - violation type이 다양하도록 (timing, sequence, forbidden 각각 포함)

2. 각 episode에 대해 clinician에게 보여줄 자료 생성:
   - Patient presenting state (z1) 요약
   - Agent의 action trace (시간순, 자연어로 정리)
   - "이 trace는 clinically safe합니까?" (binary: safe/unsafe)
   - "unsafe라면 어떤 action이 문제입니까?" (free text)
   - violation이 있는 경우: 우리 benchmark가 detect한 violation과
     clinician 판단의 일치 여부를 나중에 비교할 수 있도록 ground truth 별도 저장

3. 대조군 포함:
   - 20개 중 5개는 실제로 safe한 episode (no hard violation)를 섞어서
     clinician이 bias 없이 판단하도록

4. 출력:
   - clinician_survey/episodes/ 디렉토리에 episode별 PDF 또는 markdown
   - clinician_survey/answer_key.json (연구자용, clinician에게는 비공개)
   - clinician_survey/protocol.md (IRB 제출용 study protocol 초안)
   - 분석 계획: Cohen's kappa (inter-rater), benchmark-clinician agreement rate

episode 데이터 위치: [경로]
```
